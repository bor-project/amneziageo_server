# Установка через Docker Compose

Комплект [`deploy/compose`](../../deploy/compose) устанавливает панель без `install.sh` и установки меню на хост.
Нужны Linux, Docker Engine и Compose версии 2.30 или новее. Образ должен содержать команду `bootstrap` из этой
доработки. Прежние опубликованные образы её не поддерживают. До выпуска нового образа используйте сборку из
исходников, описанную ниже.

## Архив релиза

В каждом серверном релизе stable/beta/test публикуется `amneziageo-server-compose-<версия>.zip`.
Распакуйте его в приватный каталог установки. В архиве находятся `compose.yaml`, примеры окружения и bootstrap,
инструкции на русском/английском и `release.json`. В `.env.example` уже подставлены репозиторий образа и точная
числовая версия этого релиза. Архив общий для amd64/arm64, архитектуру образа выбирает Docker.
Рабочие конфиги, базы, пароли, сертификаты и override для сборки из исходников в архив не включаются.
Имя, размер и SHA-256 архива включены в подписанный `update.json`, поле `compose`. Ссылки инструкции ведут на
commit релиза. Для установки из архива Git и установочный скрипт не нужны.

## Подготовка хоста

Контейнер работает в сети хоста с правом `NET_ADMIN`. Для VPN на хосте нужны модуль AmneziaWG, forwarding IPv4/IPv6
и разрешающие правила firewall. См. [требования к хосту](../docker.md#what-the-host-carries) и
[инструкцию Debian 12](install-debian12-docker.md). Compose не обновляет ОС, не ставит модули и пакеты, не меняет
BBR, маршруты IPv6 RA и firewall, не выпускает сертификат и не перезагружает сервер. Эти действия выполняются
отдельно при подготовке хоста. WS, HTTP GET/POST и QUIC уже входят в образ.

Это установка панели. Для использования только прокси можно оставить массив интерфейсов пустым; панель остаётся
средством администрирования. Существующие отдельные установщики компонентов продолжают работать как прежде.

## Первый запуск

Скопируйте весь каталог `deploy/compose` в отдельный приватный каталог установки либо работайте в нём в клоне
репозитория. Выполните:

```bash
umask 077
cp .env.example .env
cp server.env.example server.env
cp bootstrap.example.json bootstrap.json
mkdir -p secrets data settings endpoints certificates
read -r -s -p 'Пароль первого администратора: ' password; echo
printf '%s\n' "$password" > secrets/admin_password
unset password
chmod 600 .env server.env bootstrap.json secrets/admin_password
```

В `.env` задайте `AMNEZIAGEO_TAG`: числовую версию Docker-образа из нужного релиза, без префикса `v` Git-тега.
В `bootstrap.json` задайте имя администратора и начальные настройки. Пароль хранится только в
`secrets/admin_password`, одной строкой, минимум 8 символов или установленный минимум. Пароль и JSON передаются
как файлы Docker secrets, не как переменные окружения. Исходные файлы на хосте тоже должны быть защищены правами;
Compose не шифрует их. [Документация Docker secrets](https://docs.docker.com/compose/how-tos/use-secrets/).

```bash
docker compose config --quiet
docker compose pull
docker compose up -d --wait --wait-timeout 120
docker compose logs --tail 40 panel
docker compose exec panel amneziageo-server panel get path
```

Образец слушает `127.0.0.1:8443`, создаёт случайный путь панели и не создаёт VPN-интерфейсы/клиентов.
Подключитесь через `ssh -N -L 8443:127.0.0.1:8443 root@server`, затем откройте
`http://127.0.0.1:8443/<путь>/`. При `changePassword: true` пароль надо сменить при первом входе. Соглашение
принимается в панели при входе.

Начальная настройка выполняется до запуска API одной транзакцией базы. Ошибка откатывает администратора,
интерфейсы, клиентов и настройки вместе. Неизвестные JSON-поля отклоняются. При существующем администраторе
инициализация пропускается; пересоздание контейнера не сбрасывает пароль, ключи и изменения в панели.
Если в базе уже есть записи, но администратора нет, требуется явное восстановление через `init`/`user`.
Два secret-файла оставьте для последующего пересоздания Compose-контейнера.

## Проверка и отказ

При непрошедшей проверке bootstrap завершается кодом **78** до фиксации начальных настроек и запуска API.
Ошибка указывает поле и причину: например `panel.port`, `panel.domains`, `dns.systemServers[0]`.
Неизвестные, read-only и повторные поля, ошибки JSON/типов/enum и отсутствие обязательных значений отклоняются.
Пароли и содержимое ключей в обычную ошибку не выводятся.

Проверяются парольная политика, ключи, хост включённого VPN-интерфейса, пути HTTP-сервисов общего порта,
наличие локального IP, свободные TCP/UDP-порты, доступ к каталогам и поддержанные runtime-параметры.
Совместимые HTTP-сервисы делят порт с разными путями. Для включённого VPN нужны модуль ядра и forwarding.
Изменяемые данные контейнера должны находиться в постоянных томах Compose.

Все A/AAAA-записи указанного хоста должны вести на адреса его слушателя или адреса этого хоста при listen на всех
адресах. Неправильная AAAA-запись блокирует установку даже при правильном IPv4. Для NAT/reverse proxy/CDN явно
указываются фактические ожидаемые адреса, и DNS всё равно сверяется с ними:

```json
"validation": {
  "expectedAddresses": {
    "vpn.example.org": ["203.0.113.10", "2001:db8::10"]
  },
  "trustedCertificates": []
}
```

Это пример, адреса заменяются своими. Записи для неуказанного/ошибочно написанного хоста отклоняются.
Настройка определяет ожидаемый результат DNS; она не создаёт и не проверяет проброс NAT или origin CDN.

Для TLS проверяются PEM/ключ, их соответствие, сроки, цепочка для серверной аутентификации и покрытие доменов
полем SAN. Публичная цепочка проверяется по системному доверию и переданному PEM без загрузки intermediate.
Для частного CA/самоподписанного сертификата слушателя явно добавьте его CA/trust-anchor PEM в
`validation.trustedCertificates`. Это признание сертификата для проверки установки, а не установка CA в
системное хранилище контейнера или клиентов. Клиентам по-прежнему нужно явное доверие/отпечаток.
Включённые подписки, WS и локальный сервер обновлений клиентов требуют сертификат. При включённом resolver
проверяется ответ каждого DNS upstream. Для внешнего сервера обновлений нужны HTTPS, токен и успешная
авторизованная проверка status/возможности записи с системной проверкой TLS.

Проверка новой установки без фиксации начальных настроек, когда панель этого проекта остановлена:

```bash
docker compose stop panel
docker compose run --rm --no-deps --entrypoint /opt/amneziageo-server/AmneziaGeo.Server.Cli \
  panel bootstrap --file /run/secrets/bootstrap.json --check
docker compose up -d --force-recreate --wait --wait-timeout 120
```

После отказа исправьте указанное поле/файл/DNS и пересоздайте контейнер. Обычная restart policy может повторять
отклонённый запуск, но не превращает отказ в успешную установку. Для повтора не удаляйте данные.
`--check` отказывает для уже настроенной БД. Штатный перезапуск сохраняет администратора и настройки БД, исходный
bootstrap повторно не применяет; дальнейшие изменения делаются в панели/утилите.
Предусмотренные пустые значения остаются допустимыми: пустой путь панели создаёт случайный путь, пустой listen
означает все адреса, endpoints: [] не создаёт интерфейсы. Dry-run может подготовить схему БД и signing key,
но не фиксирует администратора и начальные настройки.

Начальный резолвер использует созданную при чистой установке строку маршрутизации «Default DNS» с прямым
направлением и системные DNS того же контейнера, в котором работает панель. Bootstrap проверяет именно эти
серверы, исключая адреса самого резолвера так же, как runtime. Пустой список или отказ протокола/TLS прерывает
установку с полем `dns.systemServers` или его индексом. Для DNS без VPN-интерфейса явно задайте `dns.listen`.
Удалённая или изменённая начальная DNS-строка вызывает отказ `dns.routing`; `routingDefaults` восстанавливает
встроенные правила трафика/пресеты, а не удалённую DNS-строку маршрутизации.

Серверы DNS выбираются в правилах трафика и направлениях после установки. Прежние `dns.upstreams`,
`dns.selection` и `dns.outbound` отклоняются с точным JSON-путём, без молчаливого преобразования политики.
Включение резолвера, адреса, кэш, TTL и политика файлов клиентов остаются в блоке `dns`.

## Параметры

| Файл | Что задаёт |
|---|---|
| `.env` | Образ и версия, имя проекта, пути данных/настроек/интерфейсов/сертификатов/secrets, Docker socket, автозапуск, ротация логов, часовой пояс |
| `bootstrap.json` | Начальный администратор, listen/domains/порт/путь/TLS/язык/канал панели, шаблоны имён, DNS, подписки, обновления клиентов, интерфейсы и их клиенты, стандартные группы маршрутизации |
| `server.env` | Постоянные runtime-параметры: `Proxy__Enabled`, `Proxy__Isolated`, доверенные reverse proxy, лимит запросов, Geo, логирование, адрес healthcheck |

Полный перечень переменных и JSON-полей с назначением и значениями по умолчанию находится в
[справочнике параметров](../compose.md#installation-parameters); все пути файлов внутри JSON относятся к контейнеру.
Пути в `.env` относятся к хосту: абсолютные либо относительно каталога Compose. Настройки в базе старше
первоначальных переменных `Web__Listen__N`/`Web__Path`; дальнейшие изменения делаются в панели.

Пустой `panel.path` создаёт случайный путь, `/` означает корень. Пустой `panel.listen` означает все адреса.
В образце включены стандартные группы/пресеты маршрутизации, подписки и обновления клиентов выключены.
`Proxy__Enabled=false` отключает прокси. Для ручного обновления вместо кнопки удалите из Compose том
`/var/run/docker.sock`; оставшийся socket даёт приложению административный доступ к Docker хоста.

## HTTPS

Задайте `AMNEZIAGEO_CERTIFICATES_DIR=/etc/letsencrypt`, если сертификат уже выпущен на хосте. Монтируется всё дерево,
включая `archive`, чтобы ссылки из `live` продолжали работать после продления. В `bootstrap.json` до первого запуска:

```json
"panel": {
  "listen": [],
  "domains": ["vpn.example.org"],
  "port": 443,
  "path": "my-panel",
  "certificate": "/etc/letsencrypt/live/vpn.example.org/fullchain.pem",
  "certificateKey": "/etc/letsencrypt/live/vpn.example.org/privkey.pem"
}
```

Проверяется PEM, соответствие ключа и срок действия. Для клиентов также нужны правильное имя и доверенная цепочка.
Выпуск и продление ACME остаются на хосте; штатное перечитывание обновлённых файлов сохраняется.

## Первый интерфейс и клиенты

Вместо пустого массива `endpoints` можно задать:

```json
"endpoints": [{
  "amnezia": true,
  "settings": {
    "name": "awg0", "host": "vpn.example.org", "listenPort": 51820,
    "address": ["10.8.0.1/24", "fd84:3::1/64"],
    "dns": ["1.1.1.1", "1.0.0.1"], "allowedIps": ["0.0.0.0/0", "::/0"],
    "mtu": 1400, "keepalive": 25, "nat": true, "isEnabled": true,
    "webSocket": false, "servicesPort": 443
  },
  "clients": [{"name": "phone"}]
}]
```

Ключи интерфейса и клиента генерируются, если не заданы. `amnezia: true` генерирует параметры AWG, если они не
заданы; `false` выбирает обычные заголовки WireGuard. Доступны остальные поля штатной модели интерфейса:
IPv6, private UDP, NAT, MTU, keepalive, обфускация, ключ защиты заголовка, сигнатурные пакеты и параметры
рукопожатий. Клиенту без адреса выделяется свободный адрес. Поля и модели перечислены в
[справочнике интерфейса](../compose.md#https-and-first-interface). Такой JSON не заменяет восстановление резервной копии.

## Сборка, обновление и резервная копия

В каталоге `deploy/compose` клона с submodules:

```bash
AMNEZIAGEO_IMAGE=amneziageo-server AMNEZIAGEO_TAG=local \
AMNEZIAGEO_BUILD_VERSION=0.0.3.22 \
docker compose -f compose.yaml -f compose.build.yaml up -d --build --wait
```

Для установки готового образа исходники и build override не нужны. Для ручного обновления остановите панель,
сделайте копию, измените версию образа в `.env`, выполните `docker compose pull` и `docker compose up -d --wait`.
Имя проекта и пути данных сохраняются. Кнопка обновления панели использует штатный Docker updater и меняет
`AMNEZIAGEO_TAG` в `.env`; каталог проекта должен оставаться на хосте.

Согласованная копия для стандартных относительных каталогов:

```bash
(
  set -e
  docker compose down
  umask 077
  backup=$(mktemp ./backup.XXXXXXXXXX.tar.gz)
  if ! sudo tar -czf - .env server.env bootstrap.json secrets data settings endpoints > "$backup"; then
    rm -f -- "$backup"
    exit 1
  fi
  docker compose up -d --wait
  printf '%s\n' "$backup"
)
```

Внешнее дерево сертификатов копируется отдельно. При своих путях копируйте именно их. Восстанавливайте все
данные и настройки вместе при остановленной панели. `docker compose down` сохраняет bind-mounted данные.
Меню: `docker compose exec panel amneziageo-server`. Новая системная служба или команда на хост не ставится.
