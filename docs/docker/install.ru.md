# Установка

Контейнер приносит только панель, утилиту, WebSocket-прокси и меню. Хост даёт ему остальное:

- модуль `amneziawg` в ядре: `modprobe amneziawg`, строка `amneziawg` в `/etc/modules-load.d/`, чтобы он поднимался с хостом;
- Docker с плагином compose и работающей службой;
- пересылку пакетов в обоих семействах: контейнер не пишет в `/proc/sys` хоста, поэтому без неё ни один интерфейс не поднимется, и применение интерфейса ответит `forwarding is off in /proc/sys/...`:

  ```
  printf 'net.ipv4.ip_forward = 1\nnet.ipv6.conf.all.forwarding = 1\n' > /etc/sysctl.d/90-amneziageo.conf
  sysctl --system
  ```

  Если хост берёт IPv6 из объявлений маршрутизатора (SLAAC), первой строкой того же файла - `net/ipv6/conf/<внешний интерфейс>/accept_ra = 2`: с включённой пересылкой ядро сразу снимает такой маршрут и новых объявлений не принимает;

- цепочку `FORWARD`, которая пропускает пакеты: Docker при старте включает пересылку сам и переводит политику цепочки в `drop`, и клиенты туннеля не выходят дальше хоста. Демон не трогает политику с `"ip-forward-no-drop": true` в `/etc/docker/daemon.json` и перезапуском `docker`. Опция только не даёт поставить `drop`, уже поставленный снимает один раз `iptables -P FORWARD ACCEPT`, для IPv6 - `ip6tables -P FORWARD ACCEPT`. Старый Docker опции не знает; ему не даёт поставить `drop` пересылка, включённая с загрузки: Docker ставит его, только когда включает пересылку сам.

Что из этого хосту не хватает, контейнер называет в своём журнале при старте. Нужны Debian 12 и новее или Ubuntu на amd64 или arm64, права root, публичный адрес и около 2 ГБ свободного места на диске.

## Одной командой

Каждый релиз несёт скрипт `amneziageo-server` - [консольное меню](menu.ru.md), которое ставит панель на чистый хост и дальше обслуживает её. От root:

```
curl -fsSL https://github.com/bor-project/amneziageo_server/releases/latest/download/amneziageo-server \
  -o /usr/local/bin/amneziageo-server
chmod 755 /usr/local/bin/amneziageo-server
amneziageo-server install
```

Скрипт осматривает хост, задаёт все вопросы сразу, печатает план и после согласия делает всё по списку. На первый вопрос, `Install as`, ответьте `2` (Docker). Если на хосте нет Docker, его плагина compose или служба Docker не отвечает, скрипт печатает команды, которые ставят недостающее из репозитория Docker, и выходит, ничего не меняя; после их установки та же команда идёт дальше. Вопросы, ключи файла ответов для `install --answers <файл>` и шаги общие со службой, см. [Установка службы](../service/install.ru.md#вопросы); для Docker к ним добавляются два:

| Вопрос | По умолчанию | Ключ файла ответов |
|---|---|---|
| `Directory for compose.yaml` | `/opt/amneziageo-docker` | `docker_dir`: новый или пустой каталог |
| `Put the command amneziageo-server on the host`: меню и утилита с хоста, без входа в контейнер | да | `host_menu`: `yes` или `no` |

Короткую команду меню (`shortcut`) установка спрашивает, только если команда идёт на хост. Для Docker скрипт ещё:

- дописывает `"ip-forward-no-drop": true` в `/etc/docker/daemon.json`, если версия Docker это знает, и снимает `drop`, который Docker уже поставил на пересылку, если цепочку не держит ufw; Docker не перезапускает;
- пишет `compose.yaml` в названный каталог с образом последнего релиза канала из `ghcr.io/bor-project/amneziageo-server`, каталогами хоста для базы и настроек и сокетом Docker для обновлений, запускает контейнер и заводит первого администратора в нём;
- на хосте под ufw даёт ufw то, что панель из контейнера дать не может: порты панели и интерфейса, проход клиентов первого интерфейса (`route allow in` и `out on <интерфейс>`) и, с резолвером, их DNS к серверу (порт 53 по UDP и TCP);
- с ответом да на `Put the command amneziageo-server on the host` кладёт меню релиза в `/usr/local/bin/amneziageo-server`: оно ведёт контейнер снаружи теми же пунктами меню, в том числе теми, что меняют сам хост, а команды утилиты передаёт в контейнер (`amneziageo-server user list`); проект находит в названном каталоге или по меткам контейнера. С ответом нет команды на хосте не остаётся, и меню открывается в контейнере: `docker compose -f <каталог>/compose.yaml exec panel amneziageo-server`;
- в конце печатает каталог `compose.yaml`, порты панели и интерфейса, адрес IPv6 хоста и команду меню.

Дальше - [Первый запуск](first-run.ru.md).

### Перенос с другого сервера

`amneziageo-server install --restore <файл>` ставит контейнер и, пока он остановлен, кладёт копию базы, скачанную с другой панели, на место базы; `amneziageo-server restore <файл>` делает то же на работающей панели. Подробнее - [Установка службы](../service/install.ru.md#перенос-с-другого-сервера) и [Резервная копия](panel/overview.ru.md#резервная-копия).

## Вручную

Тот же путь по шагам руками описан в репозитории: [Панель AmneziaGeo на Debian 12 в Docker](https://github.com/bor-project/amneziageo_server/blob/master/docs/ru/install-debian12-docker.md). Коротко: модуль из PPA Amnezia, пересылка и Docker с `ip-forward-no-drop`, как выше, затем проект compose. Версия образа - версия релиза, тег `latest` ведёт на последний обычный релиз; образ собран для amd64 и arm64.

```
VER=<версия>
mkdir -p /opt/amneziageo-docker /var/lib/amneziageo-server /etc/amneziageo-server /etc/amnezia/amneziawg
cd /opt/amneziageo-docker
printf 'AMNEZIAGEO_TAG=%s\n' "$VER" > .env
cat > compose.yaml <<'EOF'
name: amneziageo-server

services:
  panel:
    image: ghcr.io/bor-project/amneziageo-server:${AMNEZIAGEO_TAG:-latest}
    network_mode: host
    cap_add:
      - NET_ADMIN
    env_file:
      - path: server.env
        required: false
    volumes:
      - /var/lib/amneziageo-server:/var/lib/amneziageo-server
      - /etc/amneziageo-server:/etc/amneziageo-server
      - /etc/amnezia/amneziawg:/etc/amnezia/amneziawg
      - /var/run/docker.sock:/var/run/docker.sock
    logging:
      driver: json-file
      options:
        max-size: 10m
        max-file: "3"
    restart: unless-stopped
EOF
docker compose pull
docker compose up -d
docker compose exec panel amneziageo-server init --user admin
```

- `network_mode: host` и `NET_ADMIN`: панель поднимает интерфейсы и пишет правила в ядре хоста, поэтому сеть у неё хостовая.
- Каталоги хоста вместо томов: база и ключ подписи лежат на виду, копировать и возвращать их просто. `deploy/docker/compose.yaml` репозитория, который собирает образ из исходников, держит их в томах `data` и `settings`.
- `/var/run/docker.sock`: через него панель обновляет себя кнопкой, пересоздавая свой контейнер на новом образе. Сокет даёт контейнеру хост целиком: кто владеет панелью, владеет и хостом. Без этой строки обновление остаётся ручным.
- Версия берётся из `.env` рядом с `compose.yaml`: обновление кнопкой пишет туда новый тег, и `docker compose up -d` руками потом поднимает ту же версию.
- `server.env` рядом с `compose.yaml` принимает те же переменные, что `/etc/amneziageo-server/server.env` у службы. Сертификат читается внутри контейнера, поэтому его каталог тоже идёт в `volumes`: `/etc/letsencrypt:/etc/letsencrypt:ro`; меню добавляет эту строку в `compose.override.yaml` само.
- `init --user` в контейнере обязателен: учётные записи хоста в него не заходят.

Проверка здоровья спрашивает `/api/health` по адресу, который панель пишет в файл `health` рядом с базой при старте, так что следует за панелью на другой порт, путь и TLS; `AMNEZIAGEO_HEALTH` в окружении задаёт другой адрес.

## Обновление

Панель ставит новый релиз сама, когда `compose.yaml` даёт ей сокет демона. Раз в 12 часов она спрашивает GitHub о релизах, проверяет подпись манифеста `update.json` и показывает новый релиз в шапке «Обзора» рядом со своей версией. Кнопка «Обновить» тянет образ релиза по дайджесту, копирует базу в `/var/lib/amneziageo-server/backup`, пишет `AMNEZIAGEO_TAG=<версия>` в `.env` проекта, останавливает панель и пересоздаёт свой контейнер на новом образе с теми же настройками: меняется только образ. Прежний контейнер ждёт под своим именем: если новый не станет здоровым за три минуты, база и `.env` возвращаются, и снова работает он. Файлы compose при этом не читаются, поэтому обновление проходит, где бы они ни лежали; `.env` берёт тег, чтобы `docker compose up -d` руками потом поднял тот же образ. Подробнее - [Обновление](panel/overview.ru.md#обновление).

Слои образа идут от тех, что меняются реже, к тем, что меняет каждый релиз, поэтому демон тянет мегабайт-другой. Интерфейсы и клиенты живут в ядре и через обновление не рвутся; прокси, резолвер, панель и подписки отсутствуют те секунды, пока контейнер стартует.

Из консоли то же делают `amneziageo-server update` и `amneziageo-server update beta` (пункты 2 и 3 меню); из контейнера сеанс меню при этом кончается, снова его открывает `docker exec -it <контейнер> amneziageo-server`. Предварительные выпуски - отметка «Получать предварительные версии» на вкладке [Сервер](panel/server.ru.md). Вручную: копия базы, новый тег, перезапуск:

```
cd /opt/amneziageo-docker
cp -a /var/lib/amneziageo-server /root/amneziageo-db-$(date -u +%Y%m%d-%H%M%S)
printf 'AMNEZIAGEO_TAG=%s\n' "<версия>" > .env
docker compose pull
docker compose up -d
```

Ручное обновление базу в сторону не копирует, поэтому копия берётся руками.

## Откат

`amneziageo-server rollback` (пункт 4 меню, с хоста) поднимает контейнер на ближайшем более старом образе того же имени, который остался на хосте, и предлагает вернуть копию базы из `/var/lib/amneziageo-server/backup`. Руками - тот же приём с прежним тегом в `.env` и `docker compose up -d`; образы прежних версий остаются на хосте (`docker images | grep amneziageo`). База остаётся такой, какой её оставила новая панель, вернуть её можно копией, пока контейнер остановлен.

## Что лежит на хосте

| Путь | Что |
|---|---|
| `/opt/amneziageo-docker/compose.yaml` | описание контейнера, в каталоге, который назвали при установке; рядом `.env` с тегом, `server.env` и `compose.override.yaml` меню |
| `/var/lib/amneziageo-server/server.db` | база: учётные записи, интерфейсы, клиенты, правила, настройки |
| `/var/lib/amneziageo-server/geo` | файлы гео-баз |
| `/var/lib/amneziageo-server/backup` | копии базы перед обновлениями и восстановлением |
| `/var/lib/amneziageo-server/update` | загрузки, журналы и запись последнего обновления |
| `/var/lib/amneziageo-server/journal.db`, `access.db` | журнал событий и журнал подключений, в копии базы не входят |
| `/etc/amneziageo-server/signing.pem` | ключ, которым подписаны токены входа |
| `/etc/amneziageo-server/proxy-<интерфейс>.env`, `.yaml` | аргументы и список целей фронта WebSocket интерфейса |
| `/etc/amnezia/amneziawg/<интерфейс>.conf` | файлы интерфейсов, которые панель читает и пишет |
| `/var/run/docker.sock` | сокет демона, через который панель обновляет себя |
| `/usr/local/bin/amneziageo-server` | меню на хосте, если при установке согласились его поставить; в образе то же меню: `docker compose exec panel amneziageo-server` |
| `/usr/local/bin/ag-s` | короткая команда меню, ссылка на `amneziageo-server`, если её поставили |

В образе: `/opt/amneziageo-server` с сервером, утилитой и веб-интерфейсом, `/usr/local/bin/wstunnel`, скрипты контейнера и меню релиза.

## Чем отличается от службы

| Что | В контейнере |
|---|---|
| фронты WebSocket | панель запускает `wstunnel` сама и перезапускает через три секунды после падения; фронты гаснут и поднимаются вместе с контейнером |
| брандмауэр | в образе нет ufw, панель кладёт свои таблицы nftables; на хосте с включённым ufw его `drop` сильнее: порты и проход клиентов первого интерфейса открывает в ufw установка, а то, что заведено потом, открывается в ufw хоста руками; панель называет такой порт закрытым и печатает команду `ufw allow <порт>` |
| учётные записи хоста | выключены: панель входит только своими учётными записями и не заводит пользователей системы |
| перезапуск из панели | сервер завершается, и политика перезапуска compose поднимает контейнер снова |
| один веб-интерфейс | отдельно не обновляется: каждый образ несёт сервер и интерфейс вместе |
| пункты меню, которые меняют хост | из контейнера откат на старый образ, удаление и сертификат Let's Encrypt отвечают, что контейнер не достаёт до хоста, а правила ufw, BBR и пересылка печатают команду для хоста; меню на хосте делает всё само |

## Удаление

Пункт 6 меню `Uninstall` с хоста спрашивает, убрать ли панель и убрать ли вместе с ней базу и настройки, затем останавливает проект compose (`down`, с томами при согласии), по желанию удаляет образы панели, убирает с хоста интерфейсы панели, её таблицы nftables и правила ufw с её пометкой и удаляет меню и его короткие команды из `/usr/local/bin`. База в `/var/lib/amneziageo-server`, настройки в `/etc/amneziageo-server` и каталог проекта остаются, если не согласиться убрать их. На хосте остаются Docker, модуль `amneziawg` и файл пересылки `/etc/sysctl.d/90-amneziageo.conf`.
