# Лимиты VPN-клиентов

Шаблон задаёт лимиты по умолчанию. У клиента можно включить полное переопределение. Каждый клиент имеет собственный расход; общий бюджет клиентов шаблона не создаётся.

## Настройки

- Скорость к клиенту и от клиента задаётся отдельно, в Мбит/с. API хранит целые бит/с: 1 Мбит/с = 1 000 000 бит/с. Ноль означает отсутствие ограничения направления; положительное значение начинается с 8 бит/с.
- Квота считает сумму приёма и передачи. API хранит байты; поле объёма панели использует 1024³ байт на ГБ, как прежняя суточная квота.
- Период: сутки с 00:00 UTC, неделя с понедельника 00:00 UTC или календарный месяц с первого числа 00:00 UTC.
- При исчерпании выбирается блокировка либо заданные скорости к клиенту и от клиента. Пониженная скорость не увеличивает более низкий базовый лимит.
- Новый период возвращает обычные скорости и доступ. Административное выключение клиента сохраняется.

На странице клиента показываются действующая политика, расход, остаток, следующий сброс и ошибка применения. «Сбросить расход» обнуляет текущий период отдельно от сохранения формы. Несохранённые поля формы остаются в черновике.

## API

Поле `limits` у шаблона и клиента:

```json
{
  "enabled": true,
  "uploadBitsPerSecond": 2000000,
  "downloadBitsPerSecond": 10000000,
  "quotaBytes": 10737418240,
  "period": "month",
  "quotaAction": "throttle",
  "exceededUploadBitsPerSecond": 64000,
  "exceededDownloadBitsPerSecond": 128000
}
```

Это фрагмент настроек, остальные поля запросов клиента/шаблона сохраняют действующий контракт. `quotaAction` принимает `block` или `throttle`. При положительной квоте и `throttle` обе пониженные скорости обязательны. Нулевая квота не ограничивает объём.

У клиента `overrideLimits=false` выбирает шаблон, `true` выбирает собственный объект. Пропущенные `limits`/`overrideLimits` и `limits:null` сохраняют записанное значение. Объект `limits` с `enabled:false` выключает новую политику. Включённая политика с нулевыми скоростями и квотой явно задаёт отсутствие новых ограничений.

`state.limits` содержит действующую политику, источник наследования, начало/конец периода, RX/TX, использованный и оставшийся объём, состояния исчерпания, снижения скорости и блокировки, фактические скорости и ошибку применения.

`POST /api/clients/{id}/limits/reset` требует `ManageClients`. Ответ: обновлённый клиент; 401 без авторизации, 403 без права, 404 для неизвестного клиента, 400 `client-quota-unavailable` без активной новой квоты. Ошибка применения возвращает `client-limits-not-applied`.

## Совместимость

Без явного включения новой политики прежний `dailyLimit` сохраняет байты, локальные сутки хоста и блокировку после исчерпания. Старые поля дневной статистики остаются дневными. Пропуск `templateId` в JSON изменения клиента сохраняет шаблон; явный `null` отсоединяет его.

При новой политике подписка использует расход текущего периода. Для блокирующей квоты `Subscription-Userinfo.total` содержит квоту; для снижения скорости он равен нулю, чтобы потребители подписки не трактовали мягкий порог как запрет подключения. Публичная страница обозначает расход «Трафик».

## Применение и учёт

Ограничение скорости применяется к внутренним адресам клиента на WG/AWG-интерфейсе: HTB/fq_codel для передачи к клиенту, ingress → собственный IFB → HTB/fq_codel для трафика от клиента. IPv4 и IPv6 клиента делят одну полосу каждого направления. Способ переноса WG-пакетов не создаёт отдельный лимит.

Источник расхода — RX/TX пира WG/AWG. Внешние пакеты прокси повторно не учитываются. Шаг наблюдения и применения квоты — 2 секунды; между наблюдениями возможен перерасход. Для клиентов с квотой счётчики сохраняются на каждом шаге, а также перед сменой состояния, ручным сбросом и штатным завершением. После аварийного сброса ядра последняя ещё не прочитанная дельта не восстанавливается.

Генерация счётчиков включает загрузку ядра, индекс интерфейса и ключ пира; управляемое пересоздание пира отмечается отдельно. Чтение и пересоздание синхронизированы. Изменение шаблона, адресов, ключа и транспорта сохраняет расход клиентской записи.

Шейпер использует `tc`, `ip`, IFB, HTB, fq_codel, flower, mirred и ingress. Чужие именованные очереди и интерфейсы не заменяются. Ошибки применения показываются у клиента; затронутый ограниченный клиент остаётся заблокированным до успешного повторного применения. Ресурсы шейпера имеют отдельную метку владельца; снятие лимитов удаляет только их.
