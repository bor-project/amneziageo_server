# {{ page.title }}

Маршрутизация решает, куда идёт трафик клиентов после сервера: через канал (туннель к другому серверу), напрямую через хост или в блок. Решает ядро, по правилам nftables, которые панель собирает из своих настроек; имена доменов превращает в адреса резолвер панели.

## Как это работает

- **Правила** читаются сверху вниз, срабатывает первое подходящее. Правило сравнивает первый пакет нового соединения: куда оно идёт (гео-ключи, домены, адреса), откуда (адреса, клиенты, интерфейсы), порты и протокол. Правило «Через канал» ставит на соединение метку канала, и соединение держится этого пути, пока живёт, даже если правила потом изменились.
- **Базовые списки** стоят перед правилами: «Блокировать» отбрасывает, «Напрямую» выпускает через хост без метки.
- **Каналы** - пути наружу: сам хост, туннель AmneziaWG к другому серверу или такой же туннель внутри WebSocket; каждый канал несёт свою метку и таблицу маршрутизации. Группа каналов под одним именем раздаёт трафик по приоритету, по кругу или по клиенту, и правило называет группу так же, как канал.
- **Списки Geo** - базы `geoip.dat` и `geosite.dat`, из которых правила и шаблоны берут диапазоны стран и домены категорий.
- **DNS** - резолвер панели отвечает клиентам на имена, спрашивает внешние серверы по HTTPS и кладёт увиденные адреса в наборы правил, которые сравнивают по имени; без него правило по домену работает только по адресам, которые резолвер спросил сам.
- **Проверка** говорит, что сделают правила с соединением к имени или адресу от такого-то клиента.

Трафик, который не подошёл ни под одно правило, идёт так, как хост сам отправил бы его. Ответ, который возвращается через канал, метки не несёт, и хост находит клиента в своих таблицах. Правила нужны интерфейсы: без интерфейса, на который приходит трафик, метить нечего.

Правила маршрутизации, каналы, группы, гео-источники и резолвер меняет роль с правом «Управление маршрутизацией»; читает любая. Набор правил, как его держит хост, печатает пункт 23 консольного меню, подпункт 12.
