# {{ page.title }}

Клиент - один пир интерфейса: пара ключей, адреса внутри туннеля и файл конфигурации, который получает устройство. Страница «Клиенты» несёт три вкладки: «Конфиги» - сами клиенты, [Шаблоны](templates.ru.html) - что клиенты получают в файле, [Пресеты маршрутизации](presets.ru.html) - списки для приложения AmneziaGeo. Одна конфигурация - одно устройство: сервер держит для ключа одного пира, и два устройства с одним файлом отбирают сессию друг у друга, см. [Одна конфигурация, одно устройство](#одна-конфигурация-одно-устройство).

Полоса над списком считает выбранных и несёт «Включить», «Отключить», «Удалить»; итог приходит строкой «Включено N из M», «Не вышло: <список>» с причинами и «Интерфейсы не приняли изменения: <список>», если ядро не взяло пиров. Список читает хост каждые две секунды.

«Добавить» открывает нового клиента. Клиентов из готовых файлов переносит [импорт](#импорт) через API или консоль.

## Клиент

Страница клиента несёт две вкладки: «Экспорт» и «Настройки» (вторая - для роли с правом «Управление клиентами»).

### Экспорт

Три карточки с QR-кодом: «QR: файл .conf» - файл клиента, «QR: ссылка vpn://» - та же конфигурация ссылкой Amnezia, «QR: подписка» - адрес подписки, пока подписки включены (иначе «Подписки выключены», «У клиента нет адреса подписки» или «У клиента нет закрытого ключа»). У каждой «Копировать текст», «Копировать картинку» и «Скачать». Картинка копируется только по HTTPS или с `localhost`, где браузер это разрешает; текст копируется всегда. Длинный список `AllowedIPs` может не поместиться в QR-код файла: тогда панель открывает карточку на ссылке, в которой он занимает куда меньше места, а если не помещается и она, пишет «Не помещается в QR-код».

{% include shot.html name="client-export" alt="Вкладка «Экспорт» клиента: QR-коды подписки, файла .conf и ссылки vpn:// с кнопками копирования и скачивания" caption="QR-коды выдуманной конфигурации." %}

Файл несёт приватный ключ клиента, адреса, серверы имён, размер пакета и обфускацию интерфейса, а под `[Peer]` публичный ключ интерфейса, общий ключ, `AllowedIPs`, `Endpoint` с хостом интерфейса и keepalive. Клиент с шаблоном берёт `AllowedIPs`, серверы имён, размер пакета и keepalive из шаблона. Интерфейс без хоста отдаёт файл без строки `Endpoint`, и такому клиенту некуда подключаться. Пока резолвер панели отвечает на адресах интерфейсов, строка `DNS` несёт адрес интерфейса клиента вместо публичных серверов, а `AllowedIPs` - и этот адрес, если диапазоны его не покрывают, см. [DNS](dns.ru.html). Клиент шаблона с [маршрутизацией по именам](templates.ru.html#маршрутизация-по-именам) получает резолвер панели единственным сервером имён и `198.19.0.0/16` в `AllowedIPs`.

Имя конфигурации в файле, ссылке и подписке собирается по шаблону имени с вкладки [Сервер](server.ru.html#шаблон-имени-конфигурации), по умолчанию `{HOST}-{INTERFACE}-{CLIENT}`.

### Настройки

| Поле | Что задаёт |
|---|---|
| Имя | до 64 знаков, одно на всю панель без учёта регистра |

| Адрес | по одному адресу из каждой сети интерфейса; панель подставляет первый свободный номер, занятый подсказывает: «Занят клиентом <имя>» |

| Шаблон | шаблон клиента или «По умолчанию» |
| Подписка | имя подписки, под которым клиент отдаётся по ссылке; одно имя у нескольких клиентов собирает их в одну подписку, пусто выводит клиента из подписок, кнопка рядом делает новое имя, см. [Подписки](subscriptions.ru.html) |

| Включено | берёт ли интерфейс клиента |
| Доступ к клиенту | «Как у интерфейса», «Закрыт», «Только сервер», «Вся сеть туннеля», см. ниже |
| Разрешить серверу отключать туннель | слать ли приложению сигнал опустить туннель при выключении клиента, по умолчанию да |
| Ограничение в день, ГБ | сколько клиент может передать за сутки в обе стороны; пусто - без ограничения |

## Доступ к клиенту

Клиента достают из туннеля только настолько, насколько разрешает его доступ: «Закрыт» - никто из туннеля не начинает соединение с ним, «Только сервер» - до него достают панель и хост, «Вся сеть туннеля» - и все клиенты интерфейса. «Как у интерфейса» берёт «Доступ к клиентам» интерфейса, с него начинает новый клиент. Панель кладёт это правилами брандмауэра интерфейса: адрес клиента со всей сетью попадает в набор интерфейса, остальное к клиентам отбрасывается. Клиенты, заведённые до появления этой настройки, получили «Закрыт».

Устройство со своей стороны пускает соединения из туннеля, только когда ему это сказано на нём: в клиенте AmneziaGeo это «Разрешить входящие подключения из VPN-сети» в настройках конфигурации или `amneziageo config inbound <имя> host` для сервера и `network` для всей сети. Файл и ссылка `vpn://` этого не несут. Сценарий целиком - [Доступ к устройству за клиентом](../recipes/reach-client.ru.html).

## Трафик

Панель читает счётчики каждого пира каждые две секунды: прирост счётчика - трафик клиента, прирост за две секунды - его скорость. Трафик дня пишется в базу каждые 30 секунд и при остановке панели вместе с последними показаниями, поэтому то, что пиры передали, пока панель не работала, засчитывается, когда она вернулась. День - день по часам хоста: в полночь его часового пояса трафик каждого клиента начинается с нуля.

«Ограничение в день» - самое большее, что клиент передаёт за день в обе стороны вместе. Когда трафик дня достигает его, панель снимает пира с интерфейса и из файла интерфейса, а список пишет «ограничение на сегодня исчерпано». В полночь, а также когда ограничение подняли или сняли, пир возвращается. Счётчики читаются каждые две секунды, так что клиент на полной скорости переходит ограничение на то, что успел за это время.

Клиент «в сети», когда его пир что-то отправил, включая keepalive, за время «Считать клиента в сети» его интерфейса (60 секунд по умолчанию), а если панели не читаются интерфейсы - когда его рукопожатие моложе трёх минут.

## Отключение клиента

Выключенный клиент уходит с интерфейса, и его устройство остаётся с туннелем, который никто не отвечает: приложение AmneziaGeo держит такой туннель, чтобы ничего не ушло мимо него, и машина, до которой добирались через туннель, остаётся недоступной. Поэтому панель сначала говорит приложению отключиться, а потом снимает клиента с интерфейса. Так работают переключатель в списке, выключение выбранных и сохранение настроек с снятой отметкой «Включено».

Сигнал идёт включённому клиенту включённого интерфейса, которого панель видит подключённым; неподключённому ничего не шлётся. Приложение AmneziaGeo для Windows, Linux и Android принимает сигнал и отключается, как по слову пользователя: туннель не поднимется, пока пользователь не подключится сам. Другое приложение, в том числе AmneziaGeo старше сигнала, его не принимает и остаётся как было.

Сигнал нужен обеим сторонам. «Разрешить серверу отключать туннель» у клиента включено, пока не снято: со снятым hello не предлагает приложению сигнал и панель его не шлёт. У приложения есть такой же переключатель в настройках конфигурации, он показывается, пока панель оставляет ему выбор; приложение, которое его выключило, говорит об этом серверу при следующем hello, и панель такому клиенту сигнал не шлёт.

Сигнал, который приложение не приняло, список показывает в колонке «Был онлайн» строкой «Сигнал не доставлен», в подсказке - причина и время: «Приложение не ответило» (нет ответа за три секунды), «На устройстве сигнал никто не принимает» (порт закрыт), «Устройство недоступно», «Ответило не приложение этого клиента», «У клиента нет адреса или ключа, чтобы достать приложение». Отметка держится, пока клиента не включили снова, не удалили или панель не перезапустилась. Чтобы послать сигнал снова, включите клиента, дождитесь подключения и выключите. Как устроен сигнал, рассказано в справке репозитория [services.md](https://github.com/bor-project/amneziageo_server/blob/master/docs/services.md#the-signal-to-disconnect).

## Одна конфигурация, одно устройство

Конфигурация несёт один приватный ключ, и сервер держит для него одного пира: одну сессию и один адрес, куда отвечает. Два устройства с одной конфигурацией отбирают пира друг у друга каждым пакетом, и каждое молчит, пока не повторит рукопожатие, то есть по 15 секунд; на стенде два устройства с одним ключом теряли 69-77% пакетов. Каждому устройству человека заводится свой клиент, а несколько клиентов одного человека собирает подписка, см. [Подписка на несколько устройств](../recipes/family.ru.html).

Охрана второго устройства выключена, пока в окружении панели не стоит `Guard__IsEnabled=true`. Включённая, она замечает пира, которого под одним ключом берут два адреса, оставляет то устройство, чья очередь, а остальные отсекает в брандмауэре по адресу и порту источника (таблица `inet amneziageo_guard`); список клиентов пишет «Второе устройство отрезано: <адреса>». Отсечение держится, пока оставленное устройство в сети, и снимается, когда оно молчит дольше «Считать клиента в сети». Охрана читает интерфейсы и меняет брандмауэр, поэтому работает от root; устройство, которое ходит между сетями, она не трогает.

## Импорт

Кнопки импорта клиентов в панели нет: клиентов из готовых файлов переносят консоль и API. Команды `amneziageo-server import peers` и `import clients` читают файлы хоста, см. [Перенос с awg-quick](interfaces.ru.html#перенос-с-awg-quick). Маршрут `POST /api/clients/import` для роли с правом «Управление клиентами» принимает `{ configId, text, prefix }`: номер интерфейса и текст, либо файл интерфейса `awg-quick`, пиры которого становятся клиентами, либо файл, в котором хост держал клиентов с приватными ключами, с префиксом IPv6 для второго адреса. Ответ говорит, сколько клиентов взято (`taken`), сколько пропущено как уже известные по публичному ключу (`held`), кого взяли под другим именем (`renamed`) и кого отказали с кодом (`refused`), и кладёт интерфейс на хост один раз. Текст без клиентов этого интерфейса получает отказ `bad-client-import`.
