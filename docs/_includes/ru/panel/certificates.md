# {{ page.title }}

Вкладка «Сертификаты» задаёт сертификат, под которым панель отвечает по HTTPS. С ним отвечают по TLS и TCP-порты сервисов интерфейсов и подписки на порту панели. Без сертификата панель отвечает открытым HTTP, а порты сервисов - под сертификатом, который панель делает себе при старте.

| Поле | Что задаёт |
|---|---|
| Домен сертификата | каталог из `/etc/letsencrypt/live`: выбор домена заполняет два пути ниже его `fullchain.pem` и `privkey.pem`; «Без сертификата» снимает сертификат; «Свой путь» открывает поля для своих файлов |
| Путь к сертификату | цепочка в PEM |
| Путь к ключу | закрытый ключ этой цепочки, берётся вместе с ней |

Сохранение читает оба файла и отказывает тому, который не загружается, с кодом, который называет файл; в силу сертификат вступает после «Перезапустить». Каталог доменов задаёт `Web__CertificateRoot`, `/etc/letsencrypt/live` по умолчанию. Файл перечитывается всякий раз, когда меняется на диске, так что продлённый сертификат берётся без перезапуска. Сертификат, которого при старте нет на диске, останавливает сервер.{% if page.kind == "docker" %} Сертификат читается внутри контейнера, поэтому его каталог должен быть в `volumes`: `/etc/letsencrypt:/etc/letsencrypt:ro`; меню добавляет эту строку само.{% endif %}

## Let's Encrypt

Сертификат на имя сервера выпускает пункт 22 консольного [меню](../menu.ru.html) `SSL Certificate Management`: он проверяет, что имя разрешается и TCP 80 свободен, ставит `certbot`, открывает 80 в ufw, выпускает сертификат с ключом RSA 2048 проверкой HTTP-01, включает таймер продления `certbot.timer`, ставит сертификат панели и предлагает открыть её на всех адресах хоста. То же делает вопрос об имени сервера при установке.

Ключ RSA нужен Android до 14-й версии: цепочка такого сертификата идёт до корня ISRG Root X1. `certbot` 2 по умолчанию выпускает ключ ECDSA с цепочкой до ISRG Root X2, этого корня в старых Android нет, и подписка там не скачивается. Сертификат того же имени с ключом ECDSA меню выпускает заново с RSA (`--force-renewal`); `certbot` старше 1.10 ключа `--key-type` не знает и выпускает RSA сам. Руками - `certbot certonly --standalone --preferred-challenges http --key-type rsa --rsa-key-size 2048 --cert-name <имя> -d <имя>`. Файлы берутся по путям из `live`, не копиями: при продлении `certbot` обновляет ссылки в `live`, а панель перечитывает файл сама. Для продления имя должно указывать на сервер, а TCP 80 оставаться доступным снаружи: `certbot` слушает его только во время проверки.

Карточка «Службы» на [Обзоре](overview.ru.html#службы) показывает каждый файл сертификата с датой окончания и предупреждает за 14 дней: «Истекает через N дн.».

Те же настройки в окружении панели: `Web__Certificate` и `Web__CertificateKey`; они действуют, пока панель не записала свой путь, см. [Первый старт](server.ru.html#первый-старт).
