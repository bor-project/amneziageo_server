# {{ page.title }}

Вкладка «Пользователи и роли» несёт три таблицы: «Пользователи», «Роли» и «Токены». В панель входят учётной записью панели по паролю; скрипты - долгоживущим токеном, который действует от имени роли.

## Пользователи

| Колонка | Что показывает |
|---|---|
| Имя | имя для входа |
| Отображаемое имя | как учётная запись подписана |
| Тип учётной записи | «Панель» или «Системная» - учётная запись, которая стоит и за пользователем хоста |
| Роль | роль или «без роли» |
| Статус | «включена» или «выключена» |

«Добавить» открывает новую учётную запись: имя (строчные буквы, цифры, точка, дефис и подчёркивание, с буквы), отображаемое имя, роль, пароль с кнопкой «Сгенерировать», «Потребовать смену пароля» (новый пользователь меняет выданный пароль при первом входе){% if page.kind == "package" %}, «Пользователь системы» с полем «Открытый ключ ssh», см. ниже{% endif %}. Страница учётной записи меняет роль и состояние, «Пароль» в меню строки ставит новый пароль, «Удалить» убирает учётную запись с её сессиями. Свой пароль каждый меняет в меню учётной записи в шапке. Пароль короче восьми знаков не принимается (`AMNEZIAGEO_MIN_PASSWORD` в окружении задаёт другой порог); десять промахов закрывают учётную запись на пятнадцать минут. Последнюю включённую учётную запись с правом «Управление доступом» нельзя понизить, выключить или удалить, и с собственной учётной записью этого тоже не сделать.

Имя, которое носит пользователь хоста, за учётной записью панели не закрепляется: «Такой пользователь есть на сервере, имя оставлено ему».

### Пользователи системы

Учётная запись с отметкой «Пользователь системы» стоит и за пользователем хоста: панель заводит пользователя (`useradd` с домашним каталогом и `/bin/bash`, или дополняет существующего), вводит его в группы `amneziageo`, которая достаёт до файлов панели, и `amneziageo-<роль>`, которая несёт роль, кладёт открытый ключ из поля в его `~/.ssh/authorized_keys`; пароля хоста не ставит, пользователь входит на хост по ключу. Файлы панели отдаются группе `amneziageo` с правами `0660`, так что член группы запускает `AmneziaGeo.Server.Cli` без `sudo`; поднятие интерфейсов всё равно требует root. Выключение закрывает вход на хост и выводит из групп, включение возвращает; удаление выводит из групп, а пользователя хоста с его домом оставляет. Смена роли переводит между группами ролей.

Пользователь хоста входит в панель только паролем панели: запрос из браузера не несёт учётной записи, под которой он работает; в консоли `whoami` показывает, что панель думает об учётной записи хоста, от которой запущена утилита. Группа `amneziageo-admin` даёт роль `admin` при входе с хоста (`Auth__HostGroups`), root считается администратором. В консольном меню пункт 7 предлагает сделать пользователя хоста администратором панели, установка - при совпадении логина первого администратора с пользователем хоста.
{% else %}
В контейнере учётные записи хоста выключены (`Auth__HostLogin=Off`, `Auth__HostUsers=false`): панель входит только своими учётными записями и пользователей системы не заводит, отметки «Пользователь системы» в форме нет.

## Роли

Право - то, что роль открывает; роль несёт набор прав, а учётная запись несёт роль.

| Право | Что открывает |
|---|---|
| Чтение состояния | чтение всего: «Обзор», списки, проверка маршрута |
| Управление клиентами | клиенты, шаблоны, пресеты маршрутизации |
| Управление интерфейсами | интерфейсы и их порты |
| Управление маршрутизацией | правила, базовые списки, каналы, гео, DNS |
| Управление доступом | «Настройки»: сервер, сертификаты, подписки, пользователи, роли, токены, диагностика, восстановление из копии |
| Обновление панели | «Обновить» на «Обзоре» |
| Скачивание бэкапа | «Скачать копию» на «Обзоре» |

Таблица «Роли» показывает код, название, права и число учётных записей. Встроенная роль `admin` несёт все права, не удаляется и не урезается: при каждом старте её права выравниваются с правами выпуска, так что новое право доходит до администратора само. Свои роли заводятся «Добавить»: код (как имя учётной записи), название и отметки прав. Роль, выданная учётным записям («Роль выдана учётным записям») или несущая токены («Под эту роль выпущены токены»), не удаляется.

## Токены

Токен для скриптов и других служб выпускается под роль и действует с её правами на момент вызова, так что смена прав роли доходит до токенов сразу. Токен не принадлежит учётной записи: выключение и удаление учётных записей его не трогают, остановить его можно только отзывом или сроком. Он начинается с `agt_`, идёт в том же заголовке `Authorization: Bearer`, что токен сессии, и хранится только хешем: секрет показывается один раз, при выпуске («Токен показывается один раз»).

| Колонка | Что показывает |
|---|---|
| Название | до 64 знаков, одно на панель |
| Роль | роль, от имени которой действует токен |
| Создан, Действует до | срок: 1-3650 дней или «без срока» |
| Использован | когда и с какого адреса токен применяли последний раз, «не использовался» |
| Статус | «действует» или «истёк» |

«Добавить» спрашивает название, роль и срок в днях, «Отозвать» в меню строки отзывает. Из консоли то же делают `amneziageo-server token list`, `token add <название> --role <роль> [--days <n>]` и `token revoke <id>`. Как токен ходит в API - [HTTP API](../../api.ru.html).
