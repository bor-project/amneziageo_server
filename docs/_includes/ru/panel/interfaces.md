# {{ page.title }}

Интерфейс - серверная сторона туннеля AmneziaWG: UDP-порт, на который приходят клиенты, ключи, адреса сети туннеля и вся обфускация профиля 3.1. В консольном меню и утилите он зовётся эндпоинтом (`endpoint`). Панель хранит настройки в своей базе и сама кладёт интерфейс в ядро: ключ, порт и обфускацию - в модуль, адреса - на интерфейс, NAT и закрытые сети - в брандмауэр. Хост, который поднимал интерфейсы через `awg-quick`, отдаёт их панели целиком, см. [Перенос с awg-quick](#перенос-с-awg-quick).

## Список

Список называет имя, хост, адрес подключения `<хост>:<порт>`, число клиентов и состояние. Под адресом включённого интерфейса названы закрытые порты, если брандмауэр хоста не пускает его UDP-порт или TCP-порт сервисов: «51820 закрыт в брандмауэре хоста» или «51820 и 8446 закрыты в брандмауэре хоста», с кнопкой «Открыть», когда панель может менять брандмауэр. Имя ведёт в настройки интерфейса, «Добавить» открывает форму нового. Бейдж «по умолчанию» у имени отмечает интерфейс, на который встаёт новый клиент, если интерфейс не назван.

## Форма

Новый интерфейс приходит заготовкой, которая уже сходится: порт 51820 или первый свободный выше него, сеть `10.8.0.1/24`, MTU 1420, keepalive 25, DNS `1.1.1.1` и `1.0.0.1`, AllowedIPs `0.0.0.0/0` и `::/0`, свежая пара ключей и случайная обфускация. Имя - первое свободное вида `awgN`; хост - тот, что назван у другого интерфейса, иначе домен сертификата панели, иначе адрес, по которому пришёл запрос, если клиенты снаружи достают его, иначе публичный IPv4 хоста. Заготовка не записывается, пока форму не сохранили.

### Основное

| Поле | Что задаёт |
|---|---|
| Имя | имя интерфейса в ядре, до 15 знаков: строчные буквы, цифры, дефис и подчёркивание, с буквы |
| Хост | адрес или имя, по которому клиенты приходят: строка `Endpoint` в файлах клиентов. Включённый интерфейс без хоста не сохраняется; выключенный может быть без него |
| Порт | UDP-порт туннеля, у каждого интерфейса свой. Закрытый брандмауэром порт назван под полем с кнопкой «Открыть» или «Открыть при сохранении» |
| Порт сервисов | TCP-порт, на котором отвечают hello, замер скорости и WebSocket, см. [Сервисы на TCP-порту](#сервисы-на-tcp-порту); пусто - номер UDP-порта. Несколько интерфейсов делят один порт сервисов |
| WebSocket прокси | нести ли туннель внутри WebSocket на порту сервисов. Не запустился - панель снимает отметку и пишет причину |
| Путь WebSocket | часть адреса, под которой приходит WebSocket: буквы, цифры, `-` и `_`, до 64 знаков; новому интерфейсу придумывается 16 знаков, интерфейсы прежних выпусков несут `v1` |
| MTU | размер пакета для клиентов, 576-9000; 0 оставляет системе |
| Адрес интерфейса | сети, которые несёт интерфейс, например `10.8.0.1/24`; клиенты получают адреса из них |
| Закрыто для клиентов | сети, в которые клиентов интерфейса не пускают, например `192.168.0.0/16` домашней сети сервера |
| Включено | кладётся ли интерфейс на хост. Выключение снимает его с хоста, клиенты теряют связь |
| По умолчанию | интерфейс, на который встаёт новый клиент: форма нового клиента выбирает его сразу, а клиент из API без `configId` встаёт на него. Отмечен всегда ровно один: первый интерфейс отмечается сам, отметка другого снимает её с прежнего, удалённый передаёт её следующему по порядку. Снять отметку можно, только отметив другой интерфейс |
| NAT для клиентов | маскировать ли то, что клиенты отправляют наружу, адресом хоста; без NAT клиенты выходят в интернет только с маршрутами к их сети |
| Доступ к клиентам | кто из туннеля может начать соединение с клиентами интерфейса: «Закрыт» - никто, «Только сервер» - панель и хост, «Вся сеть туннеля» - все клиенты интерфейса; отдельный клиент может выбрать своё, см. [Доступ к клиенту](clients.ru.html#доступ-к-клиенту) |
| Считать клиента в сети, с | сколько секунд после последнего пакета, включая keepalive, клиент считается в сети: 60 по умолчанию, от 10 до 3600 и не меньше двух keepalive. По нему идут отметка «в сети» в списке клиентов и охрана второго устройства |

### Сеть

| Поле | Что задаёт |
|---|---|
| AllowedIPs | сети, которые клиент отправляет в туннель: `0.0.0.0/0` и `::/0` - всё. Шаблон клиента заменяет это своим списком, см. [Шаблоны](templates.ru.html) |
| DNS | серверы имён для клиента, если резолвер панели не отвечает внутри туннеля, см. [DNS](dns.ru.html) |
| Keepalive | как часто клиент шлёт пустой пакет, секунд; 0 выключает |

### Ключи

«Приватный ключ» - ключ интерфейса, «Публичный ключ» считается из него и идёт клиентам; «Новая пара» делает новые. «Общий ключ» (preshared) добавляется к рукопожатию, «Сгенерировать» делает 32 случайных байта; пусто - без общего ключа. Клиент, у которого нет своего общего ключа, берёт ключ интерфейса. Приватный и общий ключи отдаются только роли с правом «Управление интерфейсами», остальным приходят пустыми.

### Обфускация

Поля профиля AmneziaWG 3.1: Jc (число мусорных пакетов), Jmin и Jmax (их размер), S1-S4 (мусор перед инициацией, ответом, cookie и пакетом данных), H1-H4 (магические заголовки: одно число или диапазон `194488238-194553774`; пусто - классические 1/2/3/4), I1-I5 (сигнатурные пакеты, до 1024 знаков). В «Дополнительно»: ключ защиты заголовка (32 байта в base64; с ним S1-S4 не меньше 12 байт), паддинг данных, смена ключа, ожидание рекея, отказ сессии, простой канала, попытки рукопожатия (число или диапазон; пусто - значение WireGuard по умолчанию), «Случайные хвосты» и «Без cookies» (обе стороны на AmneziaWG 3.1 и новее). Диапазон пишется двумя числами через дефис, ядро берёт из него случайное значение. `S1 + 56 = S2` панель не принимает: инициация и ответ стали бы одного размера.

Клиенты несут те же строки, что интерфейс, поэтому смена обфускации работающего интерфейса оставляет их без связи, пока они не получат новую конфигурацию: форма предупреждает «Клиенты перестанут подключаться, пока не получат новую конфигурацию». Интерфейс с другой обфускацией кладётся в ядро заново: модуль не убирает поля обфускации и часть изменений на месте не принимает; клиенты ложатся сверху и жмут руки снова.

### Файл интерфейса

Поле «Файл интерфейса» внизу формы нового интерфейса принимает текст файла `awg-quick` и кнопкой «Прочитать» заполняет форму из него: приватный ключ, адреса, порт, размер пакета и обфускация берутся из файла, остальное из заготовки. Сохранение - обычное добавление, с теми же проверками. Пиры того же файла становятся клиентами через [импорт](clients.ru.html#импорт) консолью или API.

## Что кладётся на хост

Включённый интерфейс кладётся на хост целиком: интерфейс добавляется, если его нет, ключ, порт и обфускация уходят в модуль, адреса ложатся на интерфейс, он поднимается с заданным MTU, и сверху ложатся его клиенты. Выключение и удаление снимают интерфейс с хоста. Пересылка пакетов в обоих семействах включается при каждом применении, поэтому перезагруженный хост получает её снова, как только сервер стартует.

Правила живут в таблице nftables `inet amneziageo_in`, которая переписывается при каждом изменении интерфейса: маскарад клиентов за адресом хоста (NAT), пропуск ответов на то, что клиент отправил, доступ из туннеля к клиентам, которые его разрешили, и отказ клиентам в закрытых сетях. Интерфейс, который уже поднят, сохраняет пиров и адреса: меняется только то, что отличается.

Панель следит за интерфейсами: после сообщения ядра об изменении интерфейсов хоста и каждые пять секунд без него. Опущенный за её спиной интерфейс поднимается снова, исчезнувший кладётся заново с ключами, адресами и клиентами, и журнал пишет об этом. Хост, который отказывает, назван в журнале один раз, и интерфейс пробуется снова раз в минуту.

Чтение и запись интерфейса требуют `CAP_NET_ADMIN`; без права панель хранит интерфейс и клиентов и пишет, что интерфейс отказал.

## Сервисы на TCP-порту

Кроме UDP-порта у включённого интерфейса есть TCP-порт - порт сервисов. На нём панель отвечает приложению AmneziaGeo клиента, подтверждающему ключи своего файла:

| Сервис | Что делает |
|---|---|
| hello | рассказывает приложению, что сервер ему предлагает: WebSocket с портом и путём, доступ из туннеля, сигнал отключения, замер скорости, адрес подписки, гео-источники панели и пресеты маршрутизации шаблона |
| скорость | отдаёт и принимает до 100 МиБ по билету из hello, чтобы приложение померило скорость до сервера внутри и снаружи туннеля |
| WebSocket | несёт туннель внутри WebSocket под путём интерфейса, пока включён «WebSocket прокси» |
| подписка | адрес подписки клиента, см. [Подписки](subscriptions.ru.html) |

Порт отвечает по TLS: под сертификатом панели, когда он есть, иначе под сертификатом, который панель делает себе при старте; приложение его не проверяет, клиента подтверждает подпись его ключами. Если порт сервисов перенесён, файл клиента несёт строку `# AmneziaGeo Services = <порт>`, другие приложения читают её как комментарий. Панель может отвечать на этом же порту и сама: достаточно назвать его на вкладке [Сервер](server.ru.html), и сервер открывает миру один TCP-порт.

Для WebSocket панель запускает по одному `wstunnel` на интерфейс на петле, с портом `61000 + id % 4000`, и список целей фронта пускает его только к UDP-порту своего интерфейса.{% if page.kind == "docker" %} Панель запускает фронт сама и перезапускает через три секунды после падения.{% else %} Фронт - служба `amneziageo-proxy@<интерфейс>` с аргументами в `/etc/amneziageo-server/proxy-<интерфейс>.env` и списком целей в `proxy-<интерфейс>.yaml`.{% endif %} Путь WebSocket не может совпадать с путём панели, подписок или WebSocket другого интерфейса на том же порту: такое сохранение отвечает «Путь на этом порту занят». Если фронт не поднялся или порт сервисов держит другая программа, панель снимает отметку «WebSocket прокси» и называет причину; упавший позже фронт и закрытый порт видны в [Службах](overview.ru.html#службы).

Сигнал отключения: выключение клиента говорит его приложению опустить туннель, см. [Отключение клиента](clients.ru.html#отключение-клиента).

## Порты в брандмауэре

Панель держит порты открытыми только там, где её об этом попросили; по умолчанию она не трогает брандмауэр хоста. Порты интерфейса (UDP-порт, TCP-порт сервисов, обе стороны пересылки через интерфейс и порт резолвера на интерфейсе, пока резолвер отвечает на его адресе), порт панели и порт подписок включаются пунктом 23 [меню](../menu.ru.html), командами `amneziageo-server endpoint open <имя>`, `panel set --opened on`, `subscriptions set --opened on` или кнопкой «Открыть» рядом с закрытым портом в панели. Панель включает переключатель и никогда не выключает его сама; сохранение формы без слова о порте оставляет переключатель как есть.

Где на хосте стоит ufw, панель даёт ему правила с пометкой в комментарии, по которой узнаёт свои:

```
ufw allow 51820/udp comment 'amneziageo awg0'
ufw allow 51820/tcp comment 'amneziageo awg0'
ufw route allow in on awg0 comment 'amneziageo awg0'
ufw route allow out on awg0 comment 'amneziageo awg0'
ufw allow 8443/tcp comment 'amneziageo panel'
```

Перед каждым изменением она читает `ufw show added`, добавляет недостающее и убирает только свои правила, которые больше никому не нужны; правило, написанное руками, остаётся. Выключенный ufw правила принимает и держит до включения, поэтому `ufw enable` на работающем сервере не рвёт туннели; включать и выключать ufw панель не берётся. Где ufw нет, панель кладёт таблицу `inet amneziageo_open` с теми же портами и интерфейсами: на хосте, который ничего не закрывает, это ничего не меняет, а на хосте с закрытыми в своей таблице портами их открывают там руками. Порт резолвера на интерфейсе, порты которого панель не держит, пускают в ufw подпункт 13 пункта 23 меню и `amneziageo-server dns open`, см. [DNS](dns.ru.html#как-это-работает).
{% if page.kind == "docker" %}
В образе ufw нет, поэтому панель в контейнере кладёт свою таблицу nftables. На хосте с включённым ufw его `drop` сильнее: такой порт панель называет закрытым с подсказкой «Порт <порт> закрыт брандмауэром сервера (ufw), а панель в контейнере до него не достаёт. Откройте порт на сервере: sudo ufw allow <порт>», а меню `amneziageo-server` на хосте открывает его пунктом 23.
{% endif %}
Закрытый порт форма называет под полем. Если панель может менять брандмауэр и у роли есть право на раздел (интерфейсы - «Управление интерфейсами», панель и подписки - «Управление доступом»), рядом стоит кнопка: «Открыть» для сохранённого порта держит его открытым сразу; «Открыть при сохранении» для нового или перенесённого порта открывает его вместе с сохранением, «Не открывать» отменяет. Новый порт на вкладках «Сервер» и «Подписки», который брандмауэр закрывает, не сохраняется, пока его не открыли, чтобы панель не уехала туда, где её никто не достанет; интерфейс сохраняется и так. Когда брандмауэр отказал, форма пишет «Сетевой экран сервера не принял порт», переключатель остаётся включённым до следующего применения.

Порт, который панель держала открытым и который переехал на другой номер, открывается на новом и закрывается на старом. С ufw форма спрашивает «Закрыть прежний порт 51820/udp?»: «Закрыть» убирает старое правило, «Оставить открытым» передаёт его хосту под комментарием `kept by amneziageo <имя>`, и дальше панель его не трогает (подсказка: «Оставленный порт останется открытым в брандмауэре сервера (ufw) как его собственное правило, панель больше не будет его трогать»). Таблица `amneziageo_open` ничего не хранит, поэтому без ufw старый порт закрывается без вопроса.

Состояние порта панель читает из `ufw status verbose`: решает первое правило, которое называет порт, иначе политика для входящих. Где ufw нет, она читает цепочки, которые ufw оставляет в nftables. Хост без того и другого ничего не говорит, и порт не называется. Порты кладутся заново при каждом сохранении, применении, открытии и удалении интерфейса, настроек панели и подписок, при перезапуске резолвера и при старте сервера, так что хост со сброшенным брандмауэром получает правила обратно, как только панель поднялась.

## Перенос с awg-quick

Хост, который поднимал интерфейсы `awg-quick`, отдаёт панели интерфейсы и клиентов из файлов:

```
amneziageo-server import endpoint /etc/amnezia/amneziawg/awg1.conf --host vpn.example.com
amneziageo-server import peers /etc/amnezia/amneziawg/awg1.conf --endpoint awg1
amneziageo-server import clients /root/awg-clients.json --endpoint awg1 --v6 <префикс>
```

`import endpoint` читает файл интерфейса в интерфейс панели с ключами и обфускацией и называет адрес для клиентов. `import peers` читает пиров того же файла: имена берутся из комментариев над ними, приватных ключей там нет, поэтому такой клиент управляется, но файла ему панель не выдаст, а клиенту, которому нужен файл, заводится новый. `import clients` читает файл, в котором хост держал клиентов с приватными ключами; `--v6` добавляет каждому адрес второго семейства по последнему числу первого. Клиент, чей публичный ключ панель уже знает, пропускается, поэтому импорт идёт дважды без удвоения; занятое имя получает номер (`anna-2`). Пункт 25 меню делает то же вопросами. В панели из этого есть поле «Файл интерфейса» формы нового интерфейса; клиентов из текста принимает `POST /api/clients/import`, см. [Импорт](clients.ru.html#импорт).

Потом остановить старые службы и запустить панель:

```
systemctl disable --now awg-quick@awg0 awg-quick@awg1
systemctl start amneziageo-server
```

Интерфейсы сохраняют ключи, порты, адреса и обфускацию из файлов, и клиенты возвращаются сами с файлами, которые уже держат. Что старые `PostUp` отбрасывали, записывается в «Закрыто для клиентов», что маскировали - это «NAT для клиентов». Старые файлы остаются на месте, и `systemctl enable --now awg-quick@awg0` возвращает хост назад, когда служба панели остановлена. Всё, что управляло пирами до панели (скрипты синхронизации, таймеры), должно остановиться, иначе двое будут отменять друг друга. Копию файлов хоста и базы панели `/var/lib/amneziageo-server/server.db` стоит сохранить до переезда.

Панель добавляет и меняет пиров интерфейса и снимает тех, кого выключила или удалила; пира, которого она не знает, оставляет на месте, и `POST /api/clients/apply` перечисляет таких как лишних. Те же клиенты пишутся в файл интерфейса в `/etc/amnezia/amneziawg`, чтобы перезагрузка их не потеряла; шапка файла до первого `[Peer]` сохраняется как есть. Каталог задаёт `Endpoints__Directory`, `Endpoints__KeepFile=false` выключает запись файла.

## Удаление

Удаление стоит на странице интерфейса: «Удалить <имя>?». Оно снимает интерфейс с хоста вместе с клиентами. Интерфейс, который называют правила маршрутизации, остаётся в них по имени: такое правило не кладётся на хост с причиной «Ни одного из интерфейсов правила нет».

## Отказы

| Сообщение | За чем стоит |
|---|---|
| Имя из строчных букв, цифр, дефиса и подчёркивания, начинается с буквы | имя пустое, длиннее 15 знаков или с другими знаками |
| Это не адрес и не имя хоста; Укажите хост, по которому клиенты подключаются к серверу | хост не разобран; включённый интерфейс без хоста |
| Порт вне диапазона 1-65535; Порт уже занят другим интерфейсом | UDP-порт |
| Адрес интерфейса не диапазон адресов; AllowedIPs не диапазон адресов; Это не адрес сервера имён; Закрытая сеть записана не диапазоном | сети и адреса |
| MTU вне диапазона 576-9000; Keepalive вне диапазона 0-65535; Не меньше двух keepalive и в пределах 10-3600 с | размеры и времена |
| Приватный ключ не 32 байта в base64; Общий ключ не 32 байта в base64; Ключ защиты заголовка не 32 байта в base64 | ключи |
| Размеры мусора не сходятся; Типы пакетов совпадают или ниже пяти; Спецпакет длиннее 1024 символов; Значение пишется числом или парой через дефис; Для ключа защиты заголовка S1-S4 должны быть не меньше 12 байт | обфускация |
| Такое имя уже занято | интерфейс с таким именем есть |
| В пути только буквы, цифры, - и _, одной частью; Путь на этом порту занят | путь WebSocket |
| В конфигурации нет ключа, нет сервера или она пуста | файл интерфейса не прочитан |

| Сетевой экран сервера не принял порт | ufw или nft отказали открыть порт |
