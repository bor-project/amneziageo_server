# {{ page.title }}

Резолвер панели отвечает клиентам туннеля на вопросы об именах сам: передаёт вопрос внешнему серверу, по HTTPS, пока не сказано иначе, отдаёт ответ клиенту и кладёт увиденные адреса в наборы правил, которые сравнивают по этому имени. Так работает правило по домену: ядро решает по адресу, а адреса приносит резолвер. Заодно вопросы клиентов не уходят с сервера открытым DNS.

Свежая панель держит резолвер выключенным: клиенты получают в конфигурации серверы имён и спрашивают их через туннель. Включают его вопрос установки, пункт 29 консольного меню `DNS for Clients`, команда `amneziageo-server dns on` или отметка «Отвечать клиентам» здесь. Выключенный резолвер не работает, не держит порт и не держит соединений с внешними серверами.

## Состояние

Над настройками страница показывает, что делает резолвер: «Работает» или «Остановлен», «Слушает» с адресами, которые он взял, «Запросов», «Из кэша», «Без ответа», «Адресов в наборах», «В очереди» и «Правил по именам». Сбой стоит в той же строке: ни один внешний сервер не отвечает (`no name server answers: ...`), канал выключен, нет адреса, на котором отвечать (`the resolver does not run yet: there is no address to answer the clients on`, пока нет ни одного интерфейса).

## Резолвер

| Поле | Что задаёт |
|---|---|
| Отвечать клиентам | работает ли резолвер |
| Порт | порт вопросов, 53 по умолчанию; порт ниже 1024 требует `CAP_NET_BIND_SERVICE` |
| Слушать на адресах | адреса, на которых принимаются вопросы; пусто - адреса интерфейсов панели. Адреса, которого нет на хосте, пропускается |
| Внешние серверы | серверы имён, которым передаются вопросы, и как каждый спрашивается, см. ниже |
| Спрашивать через канал | канал или группа, через которые уходят вопросы; «Через хост» - выход самого хоста |

Внешний сервер называется адресом, а не именем, чтобы ничего не разрешать заранее:

| Запись | Как спрашивается |
|---|---|
| `https://1.1.1.1/dns-query`, `https://9.9.9.9:5053/dns-query` | DNS через HTTPS, порт 443 и путь `/dns-query`, если не написаны другие |
| `tls://1.1.1.1`, `tls://1.1.1.1:853` | DNS через TLS, порт 853 |
| `1.1.1.1`, `8.8.8.8:5300`, `[2606:4700:4700::1111]:53` | открытым DNS: UDP, и TCP для клиента, который пришёл по TCP |

Свежая панель спрашивает `https://1.1.1.1/dns-query` и `https://8.8.4.4/dns-query`; `amneziageo-server dns set --upstreams default` возвращает к ним. Сертификат сервера проверяется по адресу под доверенными корнями хоста; Cloudflare, Google и Quad9 несут адреса в сертификатах. Серверы спрашиваются по порядку; тот, что не ответил, на тридцать секунд уходит в конец и спрашивается в стороне, чтобы клиенты его не ждали. На открытый DNS ничего не падает само: он спрашивается, только где записан. Когда три вопроса подряд не нашли сервера, сбой встаёт в состояние и в журнал, и службы считают резолвер неработающим, пока сервер не ответит.

«Спрашивать через канал» ставит на вопросы метку канала, так что ответы приходят оттуда, куда уйдёт трафик; без этого там, где локальная сеть отвечает о сервисе иначе, чем сеть за каналом, правило по имени наполняется чужими адресами. Канал выбирается на каждый вопрос: группа «Приоритет» отдаёт вопросы первому живому члену, «По кругу» раздаёт по очереди, «По клиенту» ведёт себя как «Приоритет», потому что все вопросы идут от хоста. Пока выбранный канал выключен или ничего не несёт, резолвер не спрашивает и отвечает клиентам `SERVFAIL`, а состояние называет причину; через хост вопросы при выбранном канале не уходят никогда. Так же разрешаются записи шаблонов клиентов и имена в проверке маршрута.

## Кэш

| Поле | Что задаёт |
|---|---|
| TTL записи, мин | сколько минут отвеченный адрес стоит в наборе правила |
| Размер кэша, записей | сколько ответов держится в памяти, 0 - не держать |
| TTL ответа: мин, с и макс, с | в какие границы зажимается время жизни ответа из кэша |

## Клиенты

| Поле | Что задаёт |
|---|---|
| Перехватывать запросы клиентов | заворачивать ли на резолвер вопросы, которые клиент послал другому серверу имён на порт 53 |
| Запрещать DNS через TLS | отбрасывать порт 853 у клиентов, пока хоть одно правило сравнивает по имени |
| Запрещать DNS через HTTPS | отбрасывать порт 443 к известным публичным серверам имён, пока хоть одно правило сравнивает по имени |

Вопрос внутри TLS или HTTPS резолвер не видит, поэтому два запрета держат клиентов на резолвере; они ложатся на хост только пока какое-то правило или базовый список сравнивает по имени. Другой сервер AmneziaGeo, который выходит через этот и спрашивает свои серверы по HTTPS, тоже попадёт под запрет: ближняя панель тогда называет внешний сервер открытым DNS (`1.1.1.1`) и спрашивает через канал, а дальняя принимает вопрос своим резолвером и спрашивает наружу по HTTPS.

## Сохранение

«Сохранить» записывает настройки, и резолвер с правилами берут их по кнопке «Перезапустить» в шапке, которая появляется, пока сохранённые настройки ждут; она перезапускает резолвер или всю панель, если и её настройки ждут. «Отмена» сбрасывает несохранённое. Изменение интерфейсов перезапускает резолвер на их адресах с теми настройками, с которыми он работает.

## Как это работает

Пока резолвер работает на порту 53 и отвечает на адресах интерфейсов, строка `DNS` файла каждого клиента несёт адрес его интерфейса вместо публичных серверов, и так же в ссылках подписки; шаблон со своими серверами имён перекрывает это, шаблон без них берёт резолвер. Где панель держит порты интерфейса открытыми в брандмауэре, она пускает клиентов интерфейса и к резолверу: порт резолвера открывается на интерфейсе для UDP и TCP, см. [Порты в брандмауэре](interfaces.ru.html#порты-в-брандмауэре).

Резолвер спрашивает имена правил и сам, не дожидаясь клиента: каждое имя, по которому сравнивает правило, в том числе имена категории `geosite:`, спрашивается, и ответы ложатся в набор правила, так что правило работает с момента сохранения, даже для сервиса, адрес которого клиент уже держит в своём кэше. Имена спрашиваются пачками по шестнадцать, не чаще двух раз в секунду и не больше 256 на правило, и спрашиваются снова, когда прошла половина «TTL записи»; имя без ответа повторяется через две секунды, и ожидание удваивается до минуты. Ключевые слова и выражения категорий не спрашиваются: у них нет имени.

Ответ, который принёс адрес, которого в наборах ещё нет, уходит клиенту, когда адрес уже в наборе, самое большее через полсекунды, так что первое соединение к нему уже идёт по правилу. Правило держит 128 новейших адресов стоящими: раз в минуту они пишутся в базу и после перезапуска возвращаются в набор до первого вопроса, так что перезагруженная машина не оставляет правило пустым.

Ответ больше, чем датаграмма клиента, уходит обрезанным с пометкой, и клиент спрашивает снова по TCP. На хост резолвер добавляет цепочку `resolve`, которая заворачивает вопросы с интерфейсов панели на резолвер, и строки с запретами 853 и 443 к наборам `doh4` и `doh6` публичных серверов.

## Имена из соединений

Клиент, который спрашивает свой сервер имён, или любой клиент при выключенном резолвере, идёт на адрес, которого ни один ответ панели не нёс. Поэтому панель умеет читать имя из самого соединения, пока хоть одно правило сравнивает по имени: имя сервера из первого сообщения TLS на TCP 443, заголовок `Host` на TCP 80 и имя сервера из первых пакетов QUIC на UDP 443. Адрес ложится в наборы правил, под которые попало имя, на «TTL записи».

Чтение выключено, пока в окружении панели не стоит `Names__IsEnabled=true`; с ним первое соединение к адресу панель забирает себе (TPROXY на порт 7319), читает имя, решает по правилам, как проверка маршрута, кладёт адрес в наборы и ведёт соединение сама через канал правила, через хост или никуда для блокирующего правила; следующие соединения к адресу решает ядро. Берутся только соединения к портам 80 и 443 публичных адресов, не больше 300 в секунду и 4096 разом. Что из этого работает, показывает состояние резолвера, а соединения, которые панель вела сама, попадают в [журнал подключений](diagnostics.ru.html#журнал-подключений). Подробности - в справке репозитория [dns.md](https://github.com/bor-project/amneziageo_server/blob/master/docs/dns.md#names-read-out-of-the-connections).

## Отказы

| Сообщение | За чем стоит |
|---|---|
| Не задан ни один внешний сервер; Адрес внешнего сервера не разобран | «Внешние серверы» |
| Адрес, на котором слушать, не разобран; Порт вне диапазона 1-65535 | адреса и порт |
| TTL записи вне допустимого; Размер кэша вне допустимого; TTL ответа вне допустимого | кэш |
| Такого канала нет | «Спрашивать через канал» |
