# {{ page.title }}

Правило говорит, куда идёт трафик: сравнивает, чего просит клиент, и либо отправляет через канал, либо выпускает через хост, либо отбрасывает. Правила лежат в порядке чтения, и весь набор превращается в один набор правил nftables, который хост берёт разом.

## Список

Список показывает правила в их порядке с номером, переключателем, что правило сравнивает («Куда», «Клиенты», «Порты», «Вход»), куда отправляет («Трафик»: канал или «группа»), сколько диапазонов и имён вышло («Диапазоны»), и состояние: «на хосте», «выключено», «трафик заперт» с причиной, или причину, по которой правило на хост не легло. Правило переставляется стрелками «Выше» и «Ниже» и перетаскиванием строки, пока список не отсортирован и не отфильтрован. Переключатель включает и выключает правило; выключенное правило в набор не входит.

## Форма

### Основное

{% include shot.html name="rule-form" alt="Форма нового правила: имя youtube, действие «Через канал» и цели из рецепта" caption="Правило заполняется, ещё не сохранено." %}

| Поле | Что задаёт |
|---|---|
| Включено | кладётся ли правило на хост |
| Имя | до 32 знаков |
| Действие | «Через канал», «Напрямую», «Блокировать» |
| Канал | канал или группа, через которые уходит трафик правила «Через канал» |
| Протокол | «Любой», TCP, UDP |
| Порты | порты назначения: `443`, `1000-2000` |
| Порты источника | порты, с которых идёт трафик, так же |

Форма нового правила открывается включённой: правило ляжет на хост сразу после сохранения.

### Адреса

| Поле | Что задаёт |
|---|---|
| Куда | гео-ключи, домены и диапазоны адресов, в которые идёт трафик |
| Клиенты | клиенты панели по имени: правило сравнивает трафик с их адресов и перекладывается на хост при каждом изменении клиента, так что новый адрес клиента подхватывается сам |
| Интерфейсы | интерфейсы панели по имени: правило сравнивает только трафик, пришедший на один из них |

Цель читается по виду: `geoip:ru` - страна, `geosite:youtube` - категория, `203.0.113.0/24` и `198.51.100.7` - диапазоны, остальное с точкой - домен. Домен принимается и как `domain:example.com`, диапазон как `cidr:10.0.0.0/8`, в форме списков клиента AmneziaGeo, так что список переносится с одной стороны на другую без правок. `keyword:ads` подходит под каждое имя, в котором есть слово; у ключевого слова своих адресов нет, и адреса такого правила приходят только из ответов, которые видит резолвер. Диапазоны дают `geoip:` и сети в целях, имена - `geosite:`, домены и ключевые слова. Правило без целей подходит под любой адрес, без «Клиентов» - под любого клиента, без «Интерфейсов» - под любой интерфейс.

Переименование клиента, интерфейса, канала или группы переписывает новое имя во все правила, которые их называют.

Поля «Откуда» (адреса и диапазоны клиентов) больше нет. При обновлении панель переносит адреса из него в «Клиенты»: правило называет по имени каждого клиента, чей адрес попадал под них. Правило, в котором после этого нет ни одного клиента, выключается, чтобы не стать правилом для всех; так же выключается правило, под адреса которого попало больше 64 клиентов: столько одно правило не называет. Каждое тронутое правило панель называет предупреждением в своём журнале. Клиент, заведённый после обновления, в такое правило сам не попадает: его добавляют в «Клиенты».

## Порядок

Правила читаются сверху вниз, решает первое, которое подошло. Решение принимается один раз, на первом пакете соединения: правило «Через канал» ставит метку канала, и она держится на соединении; соединение без метки идёт туда, куда его отправил бы хост. Соединение остаётся на своём пути и после смены правил, и после того, как его адрес позже попал в набор другого правила. Правило «Блокировать» отбрасывает новое соединение, открытое до правила живёт, пока не кончится. Правило «Напрямую» возвращает из решения без метки, и правила ниже не читаются.

Метка возвращается только на то, что отправили клиенты: ответ, который приходит через канал, метки не несёт, и хост находит клиента в своих таблицах, а не отправляет ответ обратно в канал.

## Что не кладётся на хост

Правило входит в набор, только когда есть всё, что оно называет. Иначе список показывает причину:

| Причина | Что значит |
|---|---|
| Такого канала нет | правило называет канал, которого панель не знает |
| Канал этого правила выключен | канал выключен |
| Канал этого правила не несёт трафик | проверка канала не проходит, или интерфейс канала не поднят |
| Ни один канал не отвечает | у группы нет ни одного живого канала |
| Гео-базы ничего не дают этому правилу | в базах нет того, что правило сравнивает |
| Такого клиента нет | панель не знает ни одного из названных клиентов |
| Ни одного из интерфейсов правила нет | панель не знает ни одного из названных интерфейсов |

Первые четыре причины говорят, что правило в порядке, а пропал его выход. Тогда правило запирает трафик: оно всё равно ложится на хост, но отбрасывает свой трафик вместо того, чтобы метить, и список пишет «трафик заперт» с причиной. Через хост, под адресом самого сервера, трафик правила «Через канал» не уходит никогда; так же запирает и правило, у которого раньше была снята отметка «Не выпускать, пока канал недоступен»: этой отметки в форме больше нет. Пустая цель - ошибка самого правила, такое правило просто не ложится.

## На хосте

Правила живут в таблице nftables `inet amneziageo_rt`, которая пишется целиком и загружается одним шагом. Для каждого правила и семейства там набор диапазонов `r<id>v4` и `r<id>v6` из гео-баз и набор имён `n<id>v4` и `n<id>v6` со временем жизни, который резолвер наполняет адресами из ответов на имена правила, см. [DNS](dns.ru.html). Цепочка `prerouting` оставляет в покое всё, что пришло не на интерфейс панели, отбрасывает пакет клиента без отслеженного соединения, возвращает метку соединению, у которого она уже есть, и отдаёт цепочке `decide` только новое соединение; `decide` несёт базовые списки, а за ними правила. Набор целиком печатает пункт 23 консольного меню, подпункт 12. Правила кладутся при старте панели, после каждого изменения и когда меняется набор живых каналов.

## Отказы

| Сообщение | За чем стоит |
|---|---|
| Имя пустое или слишком длинное | имя |
| Действие - канал, напрямую или блокировка; В правиле не выбран канал | действие |
| Одна из целей не гео-ключ, не домен и не диапазон | «Куда» |
| Одно из имён клиентов не годится; Одно из имён интерфейсов не годится | «Клиенты», «Интерфейсы» |
| Протокол - любой, TCP или UDP; Порт источника не порт и не диапазон портов | протокол и порты |
| В правиле слишком много условий | правило не помещается в набор |
| Такого правила нет; Такого канала нет | номер или имя, которых панель не знает |
